# The Original Quran
This project demonstrates how the Quran has been preserved since the time the Prophet Muhammad, the Messenger of Allah, delivered it to humanity.

I have created a simple, single-page HTML version of the Quran for my personal use, and you are welcome to contribute, fork, or use it as you wish.

You can see the demo at https://kaansari.github.io/originalquran/.

## Features of this Quran:
- The Quran displays the text in the original Kufic script, which was used when the Quran was first written.
- It shows the morphology of each word.
- Each verse has a play button for recitation.
- Each verse is linked to the oldest Quran manuscripts available in the world.

## Purpose
The purpose of this project is to show that the Quran we have today is exactly the same as it was during the time of the Prophet Muhammad. It allows users to easily compare the modern text with ancient manuscripts.

## Text of the Quran
The text, behind the font, is exactly the same as the Warsh/Uthmani and Pakistani/Indian scripts.

### Contribution
I need help in comparing the old manuscripts to this version of the Quran. In 99% of the cases, the script matches the Saudi/Egyptian scripts, but there are a few verses where I found minor differences. For example, "Malaika" is spelled with an Alif, and "Raai3a" is spelled with an Alif, where in the Saudi/Egyptian Quran the Alif is identified as a small Alif.

Also, the project is extremely simple single page html file.  Keep it simple so other people can easily integrate it in their works.

## Repository layout

- `src/` — the complete static website: HTML, CSS, JavaScript, fonts and browser data.
- `scripts/` — Python data preparation tools.
- `data/` — source data used by the preparation tools.
- `tests/` — automated website checks.
- `.github/workflows/` — static GitHub Pages deployment workflows.

## Run locally

Serve the website directly from `src/` using any static HTTP server. For example:

```bash
python3 -m http.server 8000 --directory src
```

Open `http://localhost:8000/`. No application build or backend is required.
Audio, sharing and externally hosted fonts require an internet connection.

## GitHub Pages deployment

Set **Settings → Pages → Source** to **GitHub Actions**, then push to `main`.
`.github/workflows/static.yml` publishes `src/` directly to GitHub Pages.

### Shared Quran reader

`index.html`, `page.html`, `warsh.html`, `writing.html`, and `quran.html` use
`src/app.js`. `quran.html` sets `quran-view` to `chapter` and specifies the vowelled
word and combined-data files through metadata. It displays the complete selected
chapter without downloading pagination data; the other readers retain page mode.
Font settings, translations, word details, audio, and loading behavior are shared.

The default `index.html` is Eastern Reading (Hafs) using `json/quranic_words.json`.
`page.html` remains available for existing bookmarks; site links now use `index.html`.
The previous home reader is available as Old Quran at `simple.html`; `warsh.html` is labeled Western Reading.

Root selection, search and verse rendering live in `src/js/root.js`; `root.html`
contains the page markup. Both readers share audio playback and word-detail popups
through `src/common.js`. The unreferenced legacy writing script has been removed.


### Pages and verse ranges

Paginated readers use the shared 604-page Madinah Hafs verse map in `src/json/pagination_madinah.json`.
Eastern Reading, Western Reading, Old Quran and the legacy Hafs URL use the same page boundaries and range controls. Under **View**, choose **Selected verses**
and set the chapter, **From verse** and **To verse** to show only that inclusive range.
Choose **Mushaf pages** to resume normal previous/next page navigation.

The map is generated by `python3 scripts/build_mushaf_pages.py` from the Quran-Center
[Hafs PageList](https://github.com/quran-center/quran-meta/blob/master/src/lists/HafsLists.ts),
retrieved November 11, 2026. The original global verse boundaries are recorded in
`data/mushaf-page-starts.json`; they are converted to this site's chapter:verse format
without changing the boundaries. Copyright (c) 2020 Quran-Center, MIT license; see
`data/mushaf-page-starts.LICENSE` and `src/json/pagination_madinah.LICENSE`.
Page boundaries follow the Mushaf; line wrapping adapts to the chosen font and screen.

Eastern, Western and Old Quran use the same reference boundaries against their existing
text datasets; their respective text and fonts are preserved. Their page bookmark is
shared as `currentPageMadinah`; Writing keeps its own practice-page bookmark.

Existing bookmarks from the old 351-page layout are translated to the corresponding
verse in the 604-page map on first use; the old bookmark is retained for compatibility.
## Indian Quran

[Indian Quran](src/indian.html) uses QUL's Qudratullah 610-page, 15-line layout
and matching IndoPak Nastaleeq text. Page and line boundaries come from the
source exports, including verses split between pages. Its bookmark is separate
from the 604-page readers. Selected-verse mode flows naturally.

The supplied archives in `tools/` are the reproducible import source:

```sh
python3 scripts/build_indian_quran.py --layout tools/json.zip --words tools/indopak-nastaleeq.json.zip
```

The importer validates all pages, all 6,236 verses and source-token coverage.
It writes `src/json/quranic_indian_words.json` and
`src/json/indian/{pagination,lines,source}.json`; `source.json`
records the archive hashes and attribution. Four explicit tokenization mappings
preserve word lookups where IndoPak splits or joins the existing reader's words.
The word export supplies the text, with the user-requested joins بَعْدَمَا at
2:181, 8:6 and 13:37. The original archives are unchanged. The combined source token at 37:130 is split into اِلْ and یَاسِیْنَ. Together
these four approved adjustments produce exactly 77,430 printed lexical tokens,
matching the shared lookup and recitation indexes one-to-one. The importer
checks that every word ID occurs exactly once, in order, with identical text
in the printed-token and indexed-word outputs. Two stale text previews in the layout
archive differ from the word export; those differences are recorded in the
provenance file, and the word export remains authoritative.

Reader editions use HTML metadata: `quran-pagination-file`, `quran-words-file`,
`quran-page-storage-key`, and optionally `quran-lines-file`, `quran-default-font`
and `quran-required-font`. Exact printed layouts use `js/reader-layout.js`;
ordinary readers retain flowing verses. The matching IndoPak font loads from
Quran Foundation's documented font CDN and requires an internet connection.
The reader waits for that font instead of displaying incompatible verse markers.

Sources: [QUL layout 12](https://qul.tarteel.ai/resources/mushaf-layout/12),
[QUL word script 59](https://qul.tarteel.ai/resources/quran-script/59),
[QUL font 242](https://qul.tarteel.ai/resources/font/242), and
[Quran Foundation font documentation](https://api-docs.quran.foundation/docs/tutorials/fonts/font-rendering/).

Browser visual comparison is still needed: this environment cannot launch Chrome.

## Section markers

Extracted reference data from the existing Indian Quran is retained for review
and future use. It is not loaded or rendered by the reader pages. The shared
word JSON files are not modified. These annotations use the Indian/Qudratullah division convention
and are anchored to shared word IDs, not printed page numbers.

```sh
python3 scripts/extract_section_markers.py
```

This creates `src/json/section_markers.json` and the readable
[position report](docs/section-markers.md). The local source contains 30 Juz
endings, 30 quarter markers, 30 half markers and 29 three-quarter markers.
The absent three-quarter marker in Juz 27 is reported rather than guessed.
The marker at 6:73 is inside a verse and retains its exact word position.

Only the four recognized section-sign categories are extracted. Other private
glyphs, pause signs, verse numbers and undecoded symbols are left alone. Indian
Quran keeps its original embedded signs. The extraction script, metadata and
position report remain available independently of the HTML and JavaScript readers.
